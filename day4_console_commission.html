Drill 1 · Breaking the sealsE5-PRO-PD-?? ⚠

Two envelopes, and the quartermaster's key

The file's last lines, one more time. Yesterday you spotted the clue without unsealing anything; today read both spares as the working code they're about to become.

# ================= SPARE CARTRIDGES =================
# To swap: delete the installed cartridge block above and
# paste one of these in its place. Nothing else changes.
#
# --- THE ROTOR (the wheel that turns itself) ---
# coded = ""
# i = 0
# for letter in message:
#     slot = 0
#     for j in range(27):
#         if RACK[j] == letter:
#             slot = j
#     coded_slot = (slot + (key + i) % 27) % 27
#     coded = coded + RACK[coded_slot]
#     i = i + 1
#
# --- THE UNBREAKABLE WHEEL (Vigenere) ---
# Add this line just above the cartridge, with the inputs:
#     keyword = input("Keyword: ")
# coded = ""
# i = 0
# for letter in message:
#     slot = 0
#     for j in range(27):
#         if RACK[j] == letter:
#             slot = j
#     kletter = keyword[i % len(keyword)]
#     kslot = 0
#     for j in range(27):
#         if RACK[j] == kletter:
#             kslot = j
#     coded_slot = (slot + kslot) % 27
#     coded = coded + RACK[coded_slot]
#     i = i + 1
# ====================================================

The seal is the # at the start of every line, and VS Code opens it with one move: select the lines, then press Ctrl+/ (on a Mac, Cmd+/). The same key seals them back. Professionals call it toggling a comment, and it is the quartermaster's key to this whole day.

Predict To install the rotor: which lines do you delete, which do you select and unseal, and what must be true of the block that ends up between the borders? Try the toggle on the rotor's lines now, both directions, without deleting anything yet.
Delete the installed block between THE CARTRIDGE borders, unseal the rotor's lines with the quartermaster's key, and move them into the slot. The contract from yesterday's ledger must survive the surgery: the block starts with coded = "" and ends with coded having grown one character per message character. Notice what the rotor brings that Caesar never had: a counter i, born at 0, ticking after every letter, read right inside the shift. That counter is the entire difference between the two machines, and you're about to watch what it does.
You should see 
The rotor's lines lose their # marks and light up as code,
then seal back to comments. Nothing has been installed yet.
Drill 2 · The rotor commissionE5-PRO-VD-?? ⚠

Install the wheel that turns itself

Make the swap for real: installed Caesar out, rotor in, one change per run. Then run this session and watch the racks.

Message: MEET AT DAWN
Key (1 to 26): 3
Predict On paper first. Caesar's drops all fell at one slant, every letter shifted the same. The rotor clicks one notch per letter: what shape will its drops paint across the racks? And the message opens M, E, E: will the two Es light the same coded tile?
A fan. Each drop slants one tile further than the one before, the offset climbing as the counter climbs, and the two Es land on different tiles, I then J, because the wheel turned between them. Keep that picture for the demo: Caesar's parallel rain, then the rotor's fan, argues better than any sentence about why counting the top letter dies against a wheel that turns itself. Your window title still says its old name; the knobs drill fixes that.
You should see (in the terminal) 
Coded: PIJZGIBJOMIA
Drill 3 · The Unbreakable Wheel commissionE5-PRO-PD-?? ⚠

The keyword takes the slot

Second swap: rotor out, Vigenère in. This spare asks for one extra line above the cartridge, printed right in its seal: keyword = input("Keyword: "). Install both, then run this session.

Message: THE EAGLE FLIES AT MIDNIGHT
Keyword: FOX
Predict The terminal will ask one question it never asked before; which, and where does that line live? And the drops: not parallel like Caesar, not a fan like the rotor. What rhythm will they follow?
The console asks Keyword:, from the one line you added above the borders, and the drops dance on the keyword's beat: three slants, F's, O's, X's, repeating every three letters as i % len(keyword) marches the march. Recruits who armored drops in the Unbreakable Wheel side mission are meeting an old friend; everyone else just installed a three-hundred-year legend from a sealed envelope. Both are fine ways to arrive. Note the key number goes unused in this cartridge; the keyword is the key, so the number can be anything the door accepts.
You should see (in the terminal) 
Coded: YVAESXLZAETHNSOEOPE EIAELVP
Drill 4 · The knobs commissionE5-PRO-PD-?? ⚠

Your name on the board, your colors, your clock

Choose your demo cartridge and keep it installed. Now the Ops Panel: one change per run, run between every line you touch.

KID_TITLE     = "THE MIDNIGHT DESK"
TRAVEL_FRAMES = 38
TILE_COLOR    = (255, 214, 140)
SIGNAL_COLOR  = (140, 200, 255)
Predict Four changes, four runs: what does each one do on screen? The title knob has a rule the message door never enforces; from yesterday's reading of draw_glyph, what happens to a lowercase title?
Your name in amber pixel letters, each letter holding the stage for exactly one second (the Day 3 hinge's 38), warmer tiles, a cooler signal. And the trap: the intake door guards the message, but nothing guards the title knob. A lowercase character isn't on the rack, the slot search keeps its starting 0, and draw_glyph paints an A in its place: a title of small letters marches across the board as a parade of As. Silent, harmless, and confusing, which is exactly the kind of bug the next drill teaches you to catch.
You should see 
Your title, your colors, one-second letters, and a run
between every single change. That's the law of the day.
Drill 5 · The Bug Hunt: one loud, one silentE5-PRO-TR-?? ⚠

Plant them, catch them, log them

Sabotage your own console twice, on purpose, and log both in the Bug Hunt Log. First the loud one: change the knob's name, not its value.

BORED_COLOR   = (15, 19, 24)

Run it, read the traceback last line first, repair it. Then the silent one:

TRAVEL_FRAMES = 0
Predict Loud: which line of the traceback names the crime, and what name does it complain about? Silent: with zero travel frames, the program runs without a single complaint. What happens to the signal's journey, and why does no line of code object?
The last line: NameError: name 'BOARD_COLOR' is not defined. The panel now defines BORED_COLOR, so when screen.fill(BOARD_COLOR) asks for the old name, nobody answers; a one-letter typo in a knob's name breaks a line far below it, and the traceback points at the victim, not the typo. The silent bug never crashes because the travel phase is a range of frames, and a range of zero frames simply never happens: the signal teleports from pulse to flash, no drop, no complaint. A crash is loud and honest; the teleport is the silent wrap's cousin. Your log entry for each: the symptom, the line, the repair.
You should see 
NameError: name 'BOARD_COLOR' is not defined
...and with TRAVEL_FRAMES = 0: no crash, no drop. The signal
teleports. Both bugs repaired before the next drill.
Drill 6 · The sixty-second demoE5-PRO-PD-?? ⚠

Run, point, tell

A commission isn't finished until it shows well. The demo is sixty seconds and three moves, rehearsed today with a classmate playing the parent:

Run: ask your parent for a short message, capitals and spaces. Type it, pick your key, and let the window do the talking. Point: one finger on the cartridge in the code, one sentence on which cipher it is. Tell: the key ceremony's law, in your own words: they could keep this whole program, and the message stays safe, because the secret was never the machine.

Predict Rehearse it once, timed. Where do the sixty seconds actually go, and which of the three moves is hardest to do without reading from the page?
The run eats most of the minute, which is fine; the window is the show. Tell is the hard one, and it's the move that separates a demo from a magic trick: any recruit can run a machine, and the one who can say why it's safe to show understands cryptography. If R gets pressed for a second parent, the replay is free. Rehearse until Tell comes out in your own words twice in a row.
You should see 
A sixty-second demo that lands: message in, window talking,
finger on the cartridge, and the key ceremony said plainly.
Hinge question · stop here until you're sureE5-PRO-VD-?? ⚠

The turning wheel's arithmetic

Part 1: the rotor is installed with key 25. Somewhere early in any long message, one letter comes out undisguised, exactly itself. Which letter number, and why? Work (25 + i) % 27 for i = 0, 1, 2.
Part 2: the Unbreakable Wheel marches FOX. List every position of the first twelve that F guards, and name the one mark doing the marching.

Part 1: the third letter. At i = 2, 25 plus 2 is 27, a full turn, and 27 % 27 is 0: a shift of nothing, and the letter walks through in plain sight. A turning wheel must pass its own zero once per lap; a demo parent who spots their own letter unchanged has caught real mathematics, not a bug. Part 2: positions 0, 3, 6, and 9, and the marching mark is %, in i % len(keyword), cycling 0, 1, 2 forever. Day 2's clock arithmetic, running your Day 4 machine.
Field Mission · The Commission

Ship your console by the deadline

The deadline law: a commission ships at the bell whether or not every wish made it in. Floors are honorable; a working Caesar console with your name on it beats an ambitious wreck.

Part A, the machine: your demo cartridge installed and verified against a hand-trace of one letter. Caesar is the floor, the rotor the middle, the Unbreakable Wheel the stretch.

Part B, the panel: your title, at least two colors of your choosing, and your timing. One change per run, every time.

Part C, the rehearsal: the sixty-second demo run twice with a classmate as the parent, once as the agent, once as the parent yourself. Log any bug the rehearsal shakes loose; a bug found today is a gift.

CONSOLE:   THE MIDNIGHT DESK
CARTRIDGE: the rotor, key chosen at demo time
PANEL:     TILE_COLOR warm, SIGNAL_COLOR cool, TRAVEL_FRAMES 38
DEMO:      Run (parent's message), Point (the counter i),
           Tell (the machine is public, the key is the secret)
BUGS:      lowercase title -> A parade, caught in rehearsal
One sheet, filled in the notebook, is the whole deliverable's paperwork. The console itself is the deliverable.
You should see 
By the bell: a named, colored, timed console with a chosen
cartridge, rehearsed twice, bugs logged, demo-ready.

Standards, pacing & evidence (teacher panel)

The pacing choice, stated plainly: Day 4 is the commission day of the console week, and it spends its zero new marks exactly as the decay schedule promises: everything on this page was owned by yesterday's Reading, and today is arrangement, repair, and ownership. The morning is the seals and the two swaps, Drills 1 to 3, about 70 minutes; the quartermaster's key (toggle comment) is the one new tool, an editor move rather than a Python mark. The afternoon is the knobs, the Bug Hunt, and the rehearsal, Drills 4 to 6 plus the hinge and the Commission, about 100, with the deadline law read aloud at the start of the build. This day fulfills two promises older pages made: the TR arc is raised to Mastery here with the Bug Hunt Log, and PD reaches Mastery through the cartridge promotions and the commissioned panel.

Where recruits actually stall: the toggle: half the room will unseal with the key and half will hand-delete # marks until shown; teach the selection first, the keystroke second. In Drill 3, the classic failure is the keyword line pasted inside the borders, which the contract's wording in Drill 1's reveal exists to prevent. The silent teleport in Drill 5 lands best if the room commits to "it will crash" or "it won't" before the run; most rooms split. Rehearsals go long when Tell is unrehearsed; the phrase to coach toward is any child's-words version of "the machine can be public, the key is the secret."
