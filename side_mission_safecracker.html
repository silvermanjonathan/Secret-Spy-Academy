The Safecracker's Ledger

A safe with a three-digit combination guards the enemy ledger. You have two ways in: turn the dial in order, or gamble on random guesses. Then the ledger itself needs searching: the strongest signal, the mole's codename. Every search is a loop, a gate, and a briefcase.

The count-up crack

The safe's combination is a number from 0 to 999. The systematic crack starts at zero and turns the dial one click at a time. It's Day 2's sentinel gate with a counter riding along.

secret = 741
guess = 0
tries = 0
while guess != secret:
    guess = guess + 1
    tries = tries + 1
print(f"The safe opens on guess {guess}, after {tries} tries.")
Predict Which line is this while's exit line? How many tries will it take, and why is the answer the combination itself? What's the worst case on this dial?
The exit line is guess = guess + 1: it's what moves the question toward no. It takes 741 tries, one click per number from 1 up to the secret, so a count-up crack always costs exactly the combination. Worst case, a secret of 999 costs 999 tries, and that ceiling is guaranteed. No luck involved either way.

Drill 2 · The gambleE5-PRO-VD-?? ⚠

The random stakeout

The other way in: guess at random, forever, until the door opens. Three spins of the Dispatcher build a three-character guess, glued together with the tally's plus. The combination is a string now, so the door compares text, and the seed makes your run match the box below.

import random

random.seed(7)
digits = "0123456789"
secret = "741"
guess = ""
tries = 0
while guess != secret:
    guess = random.choice(digits) + random.choice(digits) + random.choice(digits)
    tries = tries + 1
print(f"The safe opens after {tries} random tries.")
Predict How many different three-character guesses are possible? Could this loop, in principle, run forever? And will the seeded count land above or below Drill 1's 741?
Ten times ten times ten: 1000 possibilities. In principle the gamble could run forever, since nothing stops it re-guessing the same wrong number, and this seed happens to get lucky at 217 tries, beating the count-up. Don't be fooled. Averaged over many runs the gamble costs about a thousand tries, while the count-up carries a written guarantee of 999 or fewer. Would you bet a mission on a lucky seed? This is why safecrackers count and gamblers go broke.

Drill 3 · Pattern: best-so-farE5-PRO-PD-?? ⚠

The champion signal

Inside the safe: a ledger of intercepted signal strengths. Which transmitter is loudest? A briefcase holds the best value seen so far; a second briefcase remembers where it was seen. Every new reading challenges the champion, and only a stronger one takes the crown.

ledger = [62, 87, 45, 91, 73, 88, 54]
best = 0
slot = 0
for i in range(7):
    if ledger[i] > best:
        best = ledger[i]
        slot = i
print(f"Strongest signal: {best}, at slot {slot}.")
Predict Walk the rack. On which passes does the gate fire, and what do the two briefcases hold at the end? Then the trap: what would print if every reading in the ledger were negative?
The gate fires on passes 0, 1, and 3, as 62, 87, then 91 each beat the champion; 88 arrives too late and loses to 91. The briefcases end at 91 and slot 3. The trap: an all-negative ledger never beats the starting 0, so the program reports a champion of 0 at slot 0, a signal that was never in the ledger at all. Starting best at the rack's first reading instead of 0 fixes it, and noticing that is the difference between using a pattern and owning it.

Drill 4 · The mole huntE5-PRO-VD-?? ⚠

Searching a rack of names

The ledger's last page lists five codenames. One belongs to the mole. This is Day 2's slot search running on a rack of strings instead of a rack of letters: same loop, same gate, same briefcase.

roster = ["falcon", "osprey", "nightjar", "kestrel", "merlin"]
mole = "nightjar"
found = 0
for i in range(5):
    if roster[i] == mole:
        found = i
print(f"The mole is {roster[found]}, slot {found}.")
Predict How many times does the gate say yes? What prints? And the familiar trap: what happens if mole is a name that isn't on the roster?
Yes exactly once, on pass 2, so it prints The mole is nightjar, slot 2. A name that's not on the roster leaves found at its starting 0, and the program calmly accuses falcon, an agent who did nothing wrong. Same silent default as the Cipher Room's small h, and the fix is the same idea as Drill 3's: a starting value that can't be mistaken for a real answer.

Guarantees and gambles

Part 1: the enemy upgrades the safe to a four-digit combination. What's the new worst case for the count-up crack, and what happens to the gamble's odds on any single guess?
Part 2: in Drill 3, the ledger grows to twenty readings and the strongest is the very first one. How many times does the gate fire across the whole search?

Part 1: 9999 tries worst case, ten times the old ceiling, and each random guess now has 1 chance in 10000. One extra digit multiplies the work by ten, and that is the entire secret of strong keys: Day 2's brute-force loop cracked a 27-key wheel in a blink, and every added digit buys another factor of ten against it. Part 2: once. The first reading takes the crown on pass 0 and no later reading beats it, so the gate stays shut for nineteen passes. A quiet search is still a complete search.
Field Mission · Crack the Vault

One program, three searches

Part A, the crack: a secret of your choosing, the count-up while, and an f-string report of guesses and tries.

Part B, the ledger: your own rack of at least eight signal strengths; report the champion and the weakest signal (a second best-so-far, with the gate flipped the other way; mind Drill 3's starting-value trap).

Part C, the roster: your own codename roster and a mole search with an honest miss: start found at a slot that can't be real, and gate the report so a missing mole prints a warning instead of an accusation.

import random

# --- Part A: the crack ---
secret = 358
guess = 0
tries = 0
while guess != secret:
    guess = guess + 1
    tries = tries + 1
print(f"Safe open on {guess} after {tries} tries.")

# --- Part B: the ledger ---
ledger = [44, 90, 12, 76, 90, 31, 8, 67]
best = ledger[0]
weakest = ledger[0]
for i in range(8):
    if ledger[i] > best:
        best = ledger[i]
    if ledger[i] < weakest:
        weakest = ledger[i]
print(f"Champion {best}, weakest {weakest}.")

# --- Part C: the roster ---
roster = ["viper", "heron", "lynx", "corsair"]
mole = "petrel"
found = 99
for i in range(4):
    if roster[i] == mole:
        found = i
if found == 99:
    print("No mole on this roster. Stay sharp.")
else:
    print(f"The mole is {roster[found]}, slot {found}.")
Why start best and weakest at ledger[0]? Because the first reading is the only champion that can't be wrong. And why 99 for found? Any slot the roster can't own works; 99 just says so loudly.

Standards, pacing & evidence (teacher panel)

Where this fits: a terminal-only side mission for agents who finished Day 2 early, a Day 5 station, or homework. Forty minutes, no pygame. Nothing here is new syntax; the mission's job is to graduate three search patterns from "seen once" to "owned": the sentinel while with a counter, best-so-far with its slot, and the flat search with an honest miss. Best-so-far was stretch tier on Day 2, so this page is where mid-tier agents finally meet it with support.

Where recruits actually stall: Drill 2's gamble beating Drill 1's count is the productive surprise; let the room argue about it before the reveal, because the argument is the lesson. In Drill 3, half the room will miss that 88 loses to 91, and the trap questions in Drills 3 and 4 both hinge on starting values, which recruits find easier the second time. The Part C gate on the report is the mission's only two-branch decision; recruits who reach for a second search loop instead should re-read the brief.
