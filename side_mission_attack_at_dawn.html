The words type themselves onto the board in pixel letters. One second later the same message lands beneath them wearing shift 3 and a font made of shapes. Two fonts, one wheel, and every line is one you already own.

Drill 1 · The wheel, in terminal countryE5-PRO-VD-?? ⚠

Yesterday's machine, today's message

Before any light, the words go through the Cipher Wheel exactly as Day 2 left it: the slot search, the shift, % for the wrap, the tally on text. Type this in the terminal first. The window will use these same lines, untouched.

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
message = "ATTACK AT DAWN"
shift = 3
result = ""
for letter in message:
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    slot = (slot + shift) % 27
    result = result + rack[slot]
print("Plain:", message)
print("Coded:", result)
Predict The message has two spaces. What does each one become, and why is the answer the same one you gave on Day 2? Then: A is slot 0. What must the first letter of the coded text be?
Both spaces become C: the space is slot 26, plus 3 is 29, and % 27 brings it to 2, the same wrap Drill 4 crashed on and Drill 11 spelled in one symbol. A, slot 0, plus 3 is slot 3, D. So the coded text opens with D and shows a C wherever the message had a space. Fourteen letters in, fourteen letters out; the shape font will paint one shape per letter, so the two rows will line up column for column.

Drill 2 · Three shelves of nineE5-PRO-VD-?? ⚠

Where a letter lives decides what it looks like

A rack of 27 is three shelves of nine. The column, slot % 9, picks the color from a rack of nine names. The shelf picks the shape with a height-band gate you have used since the Safe House: slots 0 to 8 are circles, 9 to 17 squares, 18 to 26 triangles. Run it on DAWN.

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
names = ["red", "orange", "yellow", "green", "teal", "blue", "purple", "pink", "white"]
for letter in "DAWN":
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    shape = "triangle"
    if slot < 9:
        shape = "circle"
    elif slot < 18:
        shape = "square"
    print(letter, slot, names[slot % 9], shape)
Predict W is slot 22 and N is slot 13. Take nines away from each until you can't: what is left? Which shelf is each on? Will W and N share a color, a shape, both, or neither?
22 leaves 4 after two nines; 13 leaves 4 after one. Same column, so the same color: teal. Different shelves: 13 sits on the second shelf (squares) and 22 on the third (triangles). Same color, different shape. This is Day 2's clock arithmetic with a new job: nine is one shelf, and the remainder is how far along the shelf the letter sits. Every one of the 27 slots gets its own pairing, because three shelves times nine columns is exactly 27.

A letter is five strings of three marks

Day 3 Drill 3 painted a T. Here is D, the first letter of the coded text, in the same dialect: # is ink, . is air, and the painter walks rows and columns with two loops and one gate. The file keeps all 27 letters in one list called glyphs, one rack per slot, so glyphs[slot] hands the painter the right five strings.

Drill 4 · The two paintersE5-PRO-PD-?? ⚠

Two routines, five briefcases and three

These are the file's own lines. draw_glyph paints a letter from the glyph rack; draw_shape paints the same letter from the key card. Both begin with the slot search you typed in Drill 1, because both need to know where the letter lives before they can draw it. Read them side by side.

# A letter painted mark by mark: two loops and one gate (Day 3, Drill 3).
def draw_glyph(letter, x, y, size, color):
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    rows = glyphs[slot]
    for r in range(5):
        for c in range(3):
            if rows[r][c] == "#":
                pygame.draw.rect(screen, color, (x + c * size, y + r * size, size - 1, size - 1))

# A letter as a shape and a color: the column picks the color, the shelf picks the shape.
def draw_shape(letter, x, y):
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    color = colors[slot % 9]
    if slot < 9:
        pygame.draw.circle(screen, color, (x, y), 9)
    elif slot < 18:
        pygame.draw.rect(screen, color, (x - 9, y - 9, 18, 18))
    else:
        pygame.draw.polygon(screen, color, [(x, y - 10), (x - 10, y + 8), (x + 10, y + 8)])
Predict Count the # marks in the A rack: how many squares does draw_glyph paint for one A? And draw_shape has three briefcases where draw_glyph has five. Which two are missing, and why can it do without them?
Ten squares: 1 + 2 + 3 + 2 + 2 across the five rows. The missing briefcases are size and color. A shape's color comes from the key card, colors[slot % 9], and its size is written into the drawing itself: a circle of radius 9, an 18-by-18 square, a triangle 20 marks wide. The pixel painter must be told both, because the same rack of marks can be painted large or small, ink or phosphor; the shape painter has one job and one look. Nothing to run yet: both routines paint on a screen that exists only once the next drill opens the window.
Drill 5 · First light: the words appearE5-PRO-PD-?? ⚠

The watch loop, the key card, and a clock that counts letters

Window country. Every frame the board is wiped, the key card is painted top right by the Cipher Grid's own nested loop, and then the words: k counts letters as the loop walks the message, and a letter is painted only while k < shown. Below the flip, the frame clock: every fifteenth frame, shown grows by one. Run the file and watch only the top row for now.

frame = 0
shown = 0
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill((16, 20, 36))

    # the key card: the whole rack as shapes, three shelves of nine
    pygame.draw.rect(screen, (60, 70, 100), (640, 20, 226, 78), 1)
    for shelf in range(3):
        for column in range(9):
            draw_shape(rack[shelf * 9 + column], 656 + column * 24, 36 + shelf * 24)

    # top: the words, one letter every quarter second
    x = 30
    k = 0
    for letter in message:
        if k < shown:
            draw_glyph(letter, x, 120, 8, (235, 235, 235))
        x = x + 32
        k = k + 1

    pygame.display.flip()

    # the frame clock: one more letter every quarter second
    frame = frame + 1
    if frame % 15 == 0:
        shown = shown + 1
    clock.tick(60)
Predict Sixty frames a second, one letter every fifteen frames. How many seconds until the N of DAWN is on the board? And why is the gate k < shown instead of k == shown?
Fourteen letters times fifteen frames is 210 frames: three and a half seconds. The gate is k < shown because the board is wiped by screen.fill sixty times a second; a letter painted only on the frame when k == shown would show for one quarter second and vanish. Every letter that has already arrived must be repainted every frame. That is the repaint rule from Day 3, and it is why shown can simply keep counting forever: once it passes 14, every letter is already on the board and the gate stays true for all of them.
You should see A dark 900 by 300 window titled Attack at Dawn. The key card sits top right: nine colors across, circles then squares then triangles down. ATTACK AT DAWN types itself across the board in white pixel letters, one every quarter second, and holds. The terminal shows the two lines from Drill 1 and then waits. Closing the window returns the terminal.
Drill 6 · The tally and the pauseE5-PRO-VD-?? ⚠

Counting the message the long way, then waiting one second

The shapes must wait for the words. To know when the words are done, the program needs the length of the message, and this week counts with a tally: walk the message, add one per letter. Then the coded row paints a shape only while k < shown - length - 3, so the shapes start late and land one per tick, each directly under its letter. The tally sits above the watch loop, measured once; the coded row sits inside it, right after the words, repainted every frame.

# how long is the message? count it the long way, with a tally
length = 0
for letter in message:
    length = length + 1

    # below: the coded message as shapes, one second after the last letter lands
    x = 42
    k = 0
    for letter in result:
        if k < shown - length - 3:
            draw_shape(letter, x, 235)
        x = x + 32
        k = k + 1
Predict shown counts up forever. The last letter lands when shown reaches 14. At what value of shown does the first shape land, and how many seconds after the last letter is that? At what value is the board full?
The first shape is k = 0, and 0 < shown - 14 - 3 first comes true at shown = 18: four ticks after the last letter, sixty frames, exactly one second. The fourteenth shape is k = 13, true from shown = 31, frame 465, seven and three-quarter seconds in; after that the picture holds until you close it. The - 3 is the pause, and it is a number you can change: - 0 makes the first shape land the tick after the last letter. Why not ask Python for the length? Because len is not on this week's rack, and the tally is a machine you built yourself on Day 2. You will meet len soon enough, and when you do, you will already know what it counts.

# ATTACK AT DAWN
# The words appear in pixel letters. Then the coded version appears as shapes.
# Words in the terminal, play in the window. No pygame.font: a letter is a rack of marks.

import pygame

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
message = "ATTACK AT DAWN"
shift = 3

# --- terminal country: the Cipher Wheel, character for character ---
result = ""
for letter in message:
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    slot = (slot + shift) % 27
    result = result + rack[slot]
print("Plain:", message)
print("Coded:", result)

# --- the glyph rack: one letter per slot, five strings of three marks; # is ink, . is air ---
glyphs = [

pygame.init()

# A letter painted mark by mark: two loops and one gate (Day 3, Drill 3).
def draw_glyph(letter, x, y, size, color):

    for i in range(27):

    rows = glyphs[slot]

Part D, the crack (stretch): a symbol font is not a cipher; anyone holding this file reads it. The key is the shift. Trade screenshots of a long coded row with a classmate, count the most common shape, and read its letter off the key card: that letter is E in disguise, and E's slot is 4, so the shift is the difference (going around the wheel if you pass slot 0). Standards, pacing & evidence (teacher panel)

What this mission is. The Shape Font: Day 2's wheel (Drill 11 verbatim, in terminal country) feeding two painters in window country. draw_glyph is the Console's own no-font trick, five strings of three marks, so Day 3 Drill 3's T sits in the rack unchanged. draw_shape is the cheap font: slot % 9 for the column, a flat < gate for the shelf, 3 × 9 = 27 unique glyphs. The message is hardcoded so the demo is deterministic; Part B swaps in the Day 2 intake.

Deliberate calls. (1) The message length is a tally, not len(); len is off this week's rack and the tally is a machine the recruits built. (2) The pause is - 3, chosen so the first shape lands exactly 60 frames after the last letter; the drill asks recruits to derive that. (3) pygame.draw.polygon is the one new call, introduced as three corners in a list. (4) Three-mark-wide glyphs are legibly imperfect on purpose: Part C is Day 3 Drill 3's design exercise with stakes. (5) The shape font is presented as a font, not a cipher; the key is the shift (Kerckhoffs, as on the Day 2 panel), and Part D's crack proves it.

Laws honored. Flat gates only; every window uses while running: + QUIT listener + clock.tick(60) and never self-closes; no pygame.font, return values, dicts, classes, break, try/except, //, and, slicing, append, len, mouse, or KEYDOWN. Words in the terminal, play in the window; the pixel banner is the lawful loophole. One change per run. Every output in every green box was produced by running the drill, and the timing claims (210, 270, 465 frames; the sabotage's frame 165) were measured from painted frames.
