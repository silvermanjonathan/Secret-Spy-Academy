Drill 1 · Pattern: the tallyE5-PRO-VD-?? ⚠

Add up the evidence

The most useful pattern in programming: start a briefcase at 0, then let a loop add into it, one pass at a time. Programmers call it the accumulator; at this Academy it's the tally.

clues = [12, 7, 20]
total = 0
for c in clues:
    total = total + c
print("Evidence points:", total)
Predict Trace it in your Field Notebook: what does total hold after each pass? What prints at the end?
total goes 0, then 12, then 19, then 39. The line total = total + c reads strangely at first: put into the briefcase its own contents plus one more clue. Every running total you have ever seen, from game scores to shopping carts, is this exact pattern.

Drill 2 · The mirror and its shadowE5-PRO-RD-?? ⚠

== asks the same; != asks different

One equals sign puts a value in. Two equals signs ask "are these the same?" The shadow twin != asks "are these different?" The terminal answers True or False.

word = "falcon"
print(word == "falcon")
print(word == "Falcon")
print(word != "osprey")
Predict Three answers will print. Write all three, and say why the second differs from the first.
True, False, True. The terminal matches letters exactly, and a capital F is a different letter (Drill 12 yesterday, same rule). Read != out loud as "is not" and it stops being slippery. Mixing up = and == is one of the most common misfires in programming; now you can name both halves.

Drill 3 · Pattern: the counter with a gateE5-PRO-VD-?? ⚠

Count only the strong signals

A tally that adds 1 instead of the value, and only when a gate says yes.

signals = [14, 6, 22, 9]
strong = 0
for s in signals:
    if s > 10:
        strong = strong + 1
print("Strong signals:", strong)
Predict Which signals pass the gate? What does strong hold at the end?
14 and 22 pass; 6 and 9 don't. strong ends at 2. Notice the shape: a loop, a gate inside it, a counter inside the gate. Three Day 1 tools (Drill 7's patrol, Drill 9's checkpoint, Drill 4's briefcase swap), one new pattern.

Drill 4 · Pattern: best-so-farE5-PRO-VD-?? ⚠

The strongest signal

Keep a champion briefcase. Every pass, a challenger arrives; the gate decides whether the champion is replaced.

signals = [14, 6, 22, 9]
strongest = 0
for s in signals:
    if s > strongest:
        strongest = s
print("Strongest signal:", strongest)
Predict Trace strongest through all four passes. On which passes does it change, and what does it hold at the end?
It changes on pass 1 (0 becomes 14) and pass 3 (14 becomes 22); passes 2 and 4 leave it alone because 6 and 9 lose the challenge. Final answer: 22. Swap the > for < and the same pattern finds the weakest signal instead.

Drill 5 · Meet whileE5-PRO-VD-?? ⚠

The charging battery: watch, don't count

for counts. while watches: it checks its question at the top of every pass, and runs the indented lines only while the answer is yes.

battery = 10
while battery < 50:
    battery = battery + 10
    print(battery)
print("Battery charged.")
Predict Trace it: what numbers print, and does 50 itself appear? When does the last line finally run?
20, 30, 40, and yes, 50 prints. The check happens at the top: 40 is still less than 50, so the loop runs once more, adds 10, and prints 50. Only then does the check fail. Notice the add is Drill 1's tally; a while is often a tally with a finish line.

Drill 6 · Sabotage drill: the runaway loopE5-PRO-TR-?? ⚠

The loop that never stops, and how to stop it

A while must move toward no. Break that law on purpose, once, so you know the fix. Before you run this, find the stop control: the square stop button in the terminal's corner, or click in the terminal and press Ctrl+C.

battery = 10
while battery > 0:
    battery = battery + 10
    print(battery)
Predict Read the question and the add. Will the answer ever become no? What is going to happen when you run this?
Never. battery starts above 0 and only grows, so the question stays yes forever and numbers pour down the terminal until you end it. Stop it now. This is the runaway loop, and every programmer sets one off by accident sometimes. The fix is a habit: before running any while, point at the line that moves it toward no. If you can't find one, don't run it.
You should see 
20, 30, 40, 50... climbing forever until you press stop.
Then the terminal reports the program was interrupted.
Drill 7 · Pattern: the sentinel gateE5-PRO-TR-?? ⚠

Ask until the passphrase is spoken

The classic while pattern: keep asking while the answer is wrong. The exit is a word, not a count.

passphrase = "nightjar"
guess = input("Passphrase: ")
while guess != passphrase:
    print("The door stays shut.")
    guess = input("Passphrase: ")
print("The door unlocks. Come in.")
Predict Guess wrong twice, then right. How many times does "The door stays shut." print? Which line moves the loop toward no?
Twice, once per wrong guess. The line that moves it toward no is the second input(), inside the loop: it refills guess so the question can change its answer. Delete that line and the door asks once and sulks forever. The same pattern with while ask not in rack: would guard a whole gadget rack; your Field Mission door guards one passphrase.

The door stays shut.

Drill 8 · First SignalE5-PRO-PD-?? ⚠

Open a window and hold it open

You installed pygame at the door. Now the moment: a real window, the Academy's ink, one phosphor beacon. Save this as its own file and run it. Two greeting lines from pygame appear in the terminal first; that's normal. The picture is drawn once; the loop at the bottom is what keeps the window open.

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("First Signal")
clock = pygame.time.Clock()

screen.fill((27, 31, 38))
pygame.draw.circle(screen, (123, 228, 149), (320, 240), 60)
pygame.display.flip()

running = True
while running:                          # watch
    for event in pygame.event.get():    # listen
        if event.type == pygame.QUIT:
            running = False
    clock.tick(60)                      # breathe
pygame.quit()
Predict What keeps the window open, and what closes it? Which line moves this while toward no? The beacon sits at (320, 240) in a 640-by-480 window: where on the screen is that?
The while running loop holds it open: Drill 5's watcher, with nothing to count. Clicking the window's close button sends a QUIT event, the listener catches it, running = False turns the question to no, and the program reaches pygame.quit(). And (320, 240) is dead center, half of 640 and half of 480. The three color numbers are red, green, and blue, 0 to 255; the dark one is ink and the bright one is phosphor. clock.tick(60) is the loop breathing: about sixty checks a second instead of as many as the computer can manage. Every window this week sits on this exact loop.
You should see 
A dark window titled "First Signal" with one green beacon
in the center. It stays open until you close it yourself.
Drill 9 · A rule places the beacons5.OA.B.3

The beacon rule

Yesterday a rule drew signal bars in the terminal. The same idea places beacons in a window: the rule 70 + i * 100 turns the loop number into a position.

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Beacon Rule")
clock = pygame.time.Clock()

screen.fill((27, 31, 38))
for i in range(6):
    pygame.draw.circle(screen, (123, 228, 149), (70 + i * 100, 240), 30)
pygame.display.flip()

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    clock.tick(60)
pygame.quit()
Predict Fill the ordered-pairs table in your Field Notebook: (i, x) for every pass. Where does the first beacon sit, and how far apart are neighbors?
The pairs are (0, 70), (1, 170), (2, 270), (3, 370), (4, 470), (5, 570): start at 70, step by 100. Two patterns move together, the loop number and the position, and the rule is the bridge between them. Change the 100 and the whole row of beacons breathes in or out. The hold-open loop at the bottom is Drill 8's, unchanged.
You should see 
Six green beacons in a level row across the middle
of the window, evenly spaced.
Drill 10 · A list feeds the windowE5-PRO-PD-?? ⚠

Beacons sized by the rack

A list holds the data, a loop reads it, and the window shows it. Beacon i gets size sizes[i].

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Log, Drawn")
clock = pygame.time.Clock()

sizes = [10, 25, 40, 25, 10]
screen.fill((27, 31, 38))
for i in range(5):
    pygame.draw.circle(screen, (123, 228, 149), (70 + i * 125, 240), sizes[i])
pygame.display.flip()

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    clock.tick(60)
pygame.quit()
Predict Which beacon is biggest, and where does it sit? What one change makes the row shrink toward the middle instead?
The middle beacon, at x = 320, because sizes[2] is 40. To flip the shape, reorder the list: [40, 25, 10, 25, 40]. One list drives the whole picture, which is exactly how the engine you'll read on Day 3 works: its beacons live in lists, and the loop reads them out.

Drill 11 · The patrol loopE5-PRO-RD-?? ⚠

The real game loop: while running, five beats

Drill 8's loop, grown up. The drawing moves inside the loop, because now something changes on every pass. This is the pattern under every game ever made, in five beats: watch, listen, update, draw, breathe. The drone drifts until you close the window; closing it is the exit.

import pygame

pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("Patrol Drone")
clock = pygame.time.Clock()

x = 0
frame = 0
running = True
while running:                          # 1. watch
    for event in pygame.event.get():    # 2. listen
        if event.type == pygame.QUIT:
            running = False
    x = x + 3                           # 3. update
    if x > 640:
        x = 0
    screen.fill((27, 31, 38))           # 4. draw
    pygame.draw.circle(screen, (123, 228, 149), (x, 240), 20)
    pygame.display.flip()
    frame = frame + 1                   # the frame tally
    clock.tick(60)                      # 5. breathe
pygame.quit()
Predict Which line moves this while toward no, and what do you do to trigger it? What happens to the drone when x passes 640? And what is frame counting?
The exit is running = False, and you trigger it by clicking the window's close button; that arrives as a QUIT event, the listener catches it, and the watch question turns no. Until then the drone drifts right 3 pixels per pass and wraps to 0 at the edge; that if is Drill 9 from yesterday, a flat gate. Notice x = x + 3: the tally again, now moving a light across the dark. And frame is a tally of passes, one per loop; nothing reads it yet, but on Day 4 a timed gate will. Every game you've played is this loop with more inside it.
You should see 
A green drone gliding left to right across the dark
window, forever, wrapping at the edge. It stops only
when you close the window yourself.

Field Mission · The Evidence Log

Count it, guard it, set it patrolling

Part A, the Evidence Log (terminal): your own list of 5 or 6 evidence values, reported in one f-string: the total (tally), how many are over 15 (counter with a gate), and the strongest (best-so-far).

Part B, the Safe House door (terminal): your own passphrase, a sentinel while gate, an attempts counter (Drill 3's pattern inside Drill 7's loop), and an f-string report when it unlocks.

Part C, the Patrol Drone (window): your own drone in the patrol loop: your color, your speed. It must name its exit: closing the window ends it cleanly.

Suggested start: A, then B, then C, one pattern per run. House law: one change per run, and point at every while's exit line before you run it.

import pygame

# --- Part A: the evidence log ---
evidence = [18, 9, 33, 21, 12]
total = 0
strong = 0
strongest = 0
for e in evidence:
    total = total + e
    if e > 15:
        strong = strong + 1
    if e > strongest:
        strongest = e
print(f"Total: {total}  Over 15: {strong}  Strongest: {strongest}")

# --- Part B: the safe house door ---
passphrase = "nightjar"
attempts = 1
guess = input("Passphrase: ")
while guess != passphrase:
    attempts = attempts + 1
    guess = input("Passphrase: ")
print(f"The door unlocks after {attempts} attempts. The patrol begins.")

# --- Part C: the patrol drone ---
pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("Night Patrol")
clock = pygame.time.Clock()
x = 0
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    x = x + 4
    if x > 640:
        x = 0
    screen.fill((15, 19, 24))
    pygame.draw.circle(screen, (201, 139, 31), (x, 240), 18)
    pygame.display.flip()
    clock.tick(60)
pygame.quit()
Three patterns share Part A's loop; yours may use three separate loops, which is just as correct and easier to trace. Why does attempts start at 1 and not 0? Answer in your Field Notebook.

Standards, pacing & evidence (teacher panel)

The pacing choice, stated plainly: Day 2 names four patterns that add no marks (the tally, the counter with a gate, best-so-far, the sentinel gate) and introduces three marks (==, !=, while) plus the pygame vocabulary. The window loop arrives in Drill 8 already in its final shape, so Drill 11 adds only the update beat. Nothing on this page is thrown away later: the hold-open loop is the Day 4 engine's loop, the beacon rule is its draw_beacon call, the frame tally is what its timed gate reads, and the charging battery is its battery running the other way.

Where recruits actually stall: Block A (Drills 1 to 7) runs about 50 minutes; the two predictable stalls are = against == (Drill 2) and "where does the while check?" (Drill 5, the 50-prints question). Have everyone run pip install pygame at the start of the day so the install finishes during Block A. Block B (Drills 8 to 11 plus the hinge) runs about 45 minutes; the window often opens behind VS Code, and a recruit who stops the terminal instead of closing the window sees a traceback about a display that no longer exists. Both are ten-second fixes once named. Block C, the Field Mission and the Mission Debrief, needs a full 40 minutes. Protect it.
