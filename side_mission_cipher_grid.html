The Cipher Grid

The Cipher Room taught you the shift. Enemy codebreakers know the shift too. This mission issues two stronger machines: a substitution cipher built on parallel racks, and a grid that scrambles a message by reading it sideways. Stack them and you have a double lock.

Drill 1 · Two parallel racksE5-PRO-VD-?? ⚠

The Atbash machine: search one rack, read the other

The shift cipher moved letters along one rack. A substitution cipher uses two: find your letter's slot on the plain rack, then emit whatever sits in the same slot on the coded rack. This coded rack is the alphabet reversed, a cipher so old it appears in the Book of Jeremiah, with the dot standing in for the space. The engine is Day 2's slot search plus the tally; only the last line is new thinking.

plain = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
coded = "ZYXWVUTSRQPONMLKJIHGFEDCBA."
message = "MEET AT NOON"
result = ""
for letter in message:
    slot = 0
    for i in range(27):
        if plain[i] == letter:
            slot = i
    result = result + coded[slot]
print(result)
Predict Trace M, E, E through both racks. What do they become? What does a space become, and why does slot 26 matter here?
M sits in slot 12, and slot 12 of the coded rack is N. E sits in slot 4, which holds V, so the message opens NVV. The space is slot 26, and slot 26 of the coded rack is the dot: the spaces survive as dots instead of vanishing into Cs the way the shift cipher swallowed them. Two racks, same slot number, that's the whole machine.
You should see 
NVVG.ZG.MLLM
Drill 2 · Decode by swapping the racksE5-PRO-PD-?? ⚠

Search the coded rack, read the plain one

There is no separate decoder. To decode, run the same machine with the racks' jobs swapped: search for the letter on the coded rack, emit from the plain one. Two names trade places; nothing else changes.

plain = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
coded = "ZYXWVUTSRQPONMLKJIHGFEDCBA."
message = "NVVG.ZG.MLLM"
result = ""
for letter in message:
    slot = 0
    for i in range(27):
        if coded[i] == letter:
            slot = i
    result = result + plain[slot]
print(result)
Predict Which two lines changed from Drill 1? And a trap: if you ran Drill 1 unchanged on this dotted message, what would the dots turn into, and why?
The search line now reads coded[i] and the tally line reads plain[slot]; the racks traded jobs. The trap: Drill 1 searches the plain rack, and no dot lives there, so the slot search comes up empty and slot keeps its starting 0, turning every dot into a Z. That silent default is Day 2's unknown-letter rule coming back, and it's the reason the swap matters.

Drill 3 · The gridE5-PRO-VD-?? ⚠

Write it in rows, read it in columns

A transposition cipher moves no letter to a new letter; it moves every letter to a new place. Picture the 25-character message written into a 5-by-5 grid, row by row. Now read it top to bottom, column by column. In code, the grid is imaginary: the slot number row * 5 + col is Day 1's beacon rule doing the walking, and swapping which loop is outside changes the reading direction.

message = "MEET ME AT THE SAFE HOUSE"
result = ""
for col in range(5):
    for row in range(5):
        result = result + message[row * 5 + col]
print(result)
Predict The first pass has col 0, row 0: slot 0, the M. Which slots do the next four passes read, and what are the first five characters of the result?
With col pinned at 0, row climbs, so the slots are 0, 5, 10, 15, 20: straight down the first column, giving MM SH (M, M, space, S, H). Every letter of the original is still present, just re-seated, and the scramble looks nothing like a shift. Codebreakers can't crack this with a frequency count, because the letters never changed; they have to guess the grid's shape instead.
You should see 
MM SHEETAOE HFUTAEES T  E
Drill 4 · The square's secretE5-PRO-PD-?? ⚠

Run the grid on its own output

Here is the elegant part. Paste Drill 3's scrambled output in as the message and run the very same program again, changing nothing else.

message = "MM SHEETAOE HFUTAEES T  E"
result = ""
for col in range(5):
    for row in range(5):
        result = result + message[row * 5 + col]
print(result)
Predict What comes out, and why does it work? Would it still work if the grid were 5 wide but 4 tall?
The original message walks back out. Turning rows into columns twice puts every letter back in its seat, the way flipping a card twice shows its face again, but only because the grid is square: 5 by 5. A 5-by-4 grid flipped once becomes 4 by 5, and reading it with the same fives arithmetic tears the message apart. That's why the mission pads messages to 25 characters. One program, and whether it locks or unlocks depends only on what you feed it.

Hinge question · stop here until you're sureE5-PRO-VD-?? ⚠

One slot, two ciphers

Part 1: in the grid, which character does the pass with row = 2, col = 3 read from "MEET ME AT THE SAFE HOUSE"? Work the slot number first.
Part 2: through the Atbash racks, A becomes Z and Z becomes A. What becomes of B, and of the dot?

Part 1: slot 13, the E in THE. Two rows of five is 10, plus col 3 is 13. If you got H, you counted the T as slot 1; slots start at 0, Day 1's oldest law. Part 2: B becomes Y, second from each end, and the dot becomes a space, because searching the coded rack finds the dot in slot 26 and the plain rack keeps the space there. If both landed, you're ready for the double lock.
Field Mission · The Double Lock

Substitute, then scramble

Part A, lock it: take a 25-character message (capitals and spaces; pad with spaces to reach 25), run it through the Atbash machine, then feed the result to the grid. Print what comes out of each stage.

Part B, unlock it: undo the locks in reverse order: grid first (the square flips back), then the rack swap. Print the recovered message.

Part C, the exchange: pass a double-locked slip to a classmate who finished this mission. Order matters; let them discover why grid-then-Atbash won't open it.

plain = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
coded = "ZYXWVUTSRQPONMLKJIHGFEDCBA."
message = "MEET ME AT THE SAFE HOUSE"

# --- Part A: lock ---
step1 = ""
for letter in message:
    slot = 0
    for i in range(27):
        if plain[i] == letter:
            slot = i
    step1 = step1 + coded[slot]
locked = ""
for col in range(5):
    for row in range(5):
        locked = locked + step1[row * 5 + col]
print("Substituted:", step1)
print("Locked:     ", locked)

# --- Part B: unlock ---
step2 = ""
for col in range(5):
    for row in range(5):
        step2 = step2 + locked[row * 5 + col]
opened = ""
for letter in step2:
    slot = 0
    for i in range(27):
        if coded[i] == letter:
            slot = i
    opened = opened + plain[slot]
print("Unlocked:   ", opened)
Why unlock in reverse order? The grid was the outer lock, so it opens first, the same way the last coat on goes off first.

Unlocked:    MEET ME AT THE SAFE HOUSE

Choose your exit gate

Floor · approaching the mission

Middle · meets the mission

The double lock closes and opens on your own 25-character message, and you can explain why the grid opens with the same program that closed it while the Atbash needs its racks swapped.

Standards, pacing & evidence (teacher panel)

Where this fits: a terminal-only side mission for agents who finished Day 2 early, a Day 5 station, or homework. Forty minutes, no pygame, no new syntax at all: two Day 2 machines rearranged. The historical hooks are real: Atbash is a Hebrew-alphabet cipher older than Caesar's shift, and column transposition ran under real wars. The grid's slot arithmetic, row * 5 + col, is Day 1's beacon rule wearing a second costume, and it quietly rehearses the multiplication the capstone's pips use.

Where recruits actually stall: the Drill 2 swap gets half-done (one rack renamed, not both), and the silent Z-for-dot bug that follows is worth letting them meet, since the drill's trap question predicts it. In Drill 3, recruits who write the grid on paper first almost never stall; recruits who skip the paper do. Messages that aren't exactly 25 characters crash on the slot lookup, and that traceback is a friendly one: read it last line first.
