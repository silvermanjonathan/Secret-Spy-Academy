Drill 1 · Write it once, run it twiceE5-PRO-RD-?? ⚠

def: a routine filed, not yet run

def files a routine in the blueprint. Filing it runs nothing. The routine fires only when you call its name.

def hq_banner():
    print("= = = = = = = = =")
    print("  HQ TRANSMISSION")
    print("= = = = = = = = =")

hq_banner()
hq_banner()
Predict How many banners print? And if you deleted the two calls at the bottom and ran only the def block, what would print?
Two banners, one per call. Delete the calls and nothing prints at all. A def is a page in the blueprint: nothing happens until you call it. Most recruits guess wrong here, which is exactly why we run the experiment.

Drill 2 · The blank in the routineE5-PRO-RD-?? ⚠

A parameter, filled at call time

A parameter is a briefcase that belongs to the routine: empty in the blueprint, filled the moment you call. It is Day 1's briefcase, filled by the call instead of by =.

def transmit(message):
    print(f"Transmitting: {message}")

transmit("falcon is airborne")
transmit("rendezvous at dawn")
Predict Write both output lines exactly. During the second call, what value sits inside the briefcase message?
During the second call, message holds "rendezvous at dawn". Same routine, refilled briefcase. Write the def once and you can call it as many times as you like, which is the reason functions exist.

Drill 3 · Two blanks, filled in orderE5-PRO-RD-?? ⚠

Position fills the briefcases

With two parameters, the terminal fills them by position: first argument into the first briefcase, second into the second. Watch what the swapped call does.

def requisition(gadget, count):
    print(f"Issue {count} of {gadget}.")

requisition("smoke pen", 3)
requisition(3, "smoke pen")
Predict Write both output lines exactly. Is the second call a misfire, or something quieter and worse?
No misfire. The terminal happily puts 3 into gadget and the smoke pen into count, then prints nonsense with a straight face. Argument order carries the meaning. A program that's quietly wrong is more dangerous than one that crashes; remember this one at Friday's Bug Hunt.

Drill 5 · Growing a rackE5-PRO-VD-?? ⚠

append: today's one new list move, and the Dispatcher's sibling

Day 1's racks were written by hand. append adds a slot to the end of a rack, so a loop can grow one. The engine builds its beacon racks exactly this way. And random.randint(1, 6) is random.choice's sibling: choice picks from a rack you wrote; randint picks a whole number between two ends, both ends included.

import random

rack = []
for i in range(3):
    rack.append(i * 15)
print(rack)
print(len(rack))

rolls = []
for i in range(3):
    rolls.append(random.randint(1, 6))
print(rolls)
Predict The rack starts empty. What exactly is inside after the first loop, and what does len report? What would rack[0] be? Could rolls ever contain a 7, or a 0?
[0, 15, 30], and len reports 3. Each pass appends i * 15, so slot 0 holds 0, slot 1 holds 15, slot 2 holds 30; the slot numbers are Day 1's law, unchanged. rolls can never hold a 7 or a 0: randint(1, 6) stays inside its two ends, and unlike range, it includes the last one. An empty rack plus a loop of appends is how programs build collections they can't write by hand.
You should see (your rolls will differ) 
[0, 15, 30]
3
[2, 3, 1]
Drill 6 · First run of the engine5.G.A.2

Tracker Scope: run it before you touch it

Open tracker_scope_pygame.py, or copy every line below into a file with that exact name. Change nothing. Run it. That's the gate: the engine has to run unmodified on your machine before tomorrow's Commission begins. One new word inside: pygame.draw.rect draws a box from four numbers, left, top, width, height; a fifth number makes it an outline. The same trick on circle makes a ring.

import pygame, random

pygame.init()
WIDTH = 640
HEIGHT = 480
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("Tracker Scope")
clock = pygame.time.Clock()

# ---------- THE OPS PANEL (your customizations live here) ----------
BEACON_COLORS = [(123, 228, 149), (242, 233, 211), (201, 139, 31)]
BEACON_COUNT = 12
DRIFT_SPEED = 1
SWEEP_SPEED = 4
DRAIN_RATE = 1
FULL_BATTERY = 200

SCOPE_LEFT = 120
SCOPE_TOP = 40
SCOPE_SIZE = 400
CENTER_X = 320
CENTER_Y = 240
INK = (27, 31, 38)
PHOSPHOR = (123, 228, 149)
# -------------------------------------------------------------------

SCOPE_RIGHT = SCOPE_LEFT + SCOPE_SIZE
SCOPE_BOTTOM = SCOPE_TOP + SCOPE_SIZE

# Parallel lists: beacon number i is xs[i], ys[i], batteries[i], colors[i]
xs = []
ys = []
batteries = []
colors = []

for i in range(BEACON_COUNT):
    xs.append(random.randint(SCOPE_LEFT + 20, SCOPE_RIGHT - 20))
    ys.append(random.randint(CENTER_Y, SCOPE_BOTTOM - 40))
    batteries.append(random.randint(60, FULL_BATTERY))
    colors.append(random.choice(BEACON_COLORS))

def draw_scope(surface):
    pygame.draw.rect(surface, PHOSPHOR,
                     (SCOPE_LEFT, SCOPE_TOP, SCOPE_SIZE, SCOPE_SIZE), 2)
    pygame.draw.circle(surface, PHOSPHOR, (CENTER_X, CENTER_Y), 140, 1)
    pygame.draw.circle(surface, PHOSPHOR, (CENTER_X, CENTER_Y), 70, 1)
    pygame.draw.line(surface, PHOSPHOR,
                     (SCOPE_LEFT, CENTER_Y), (SCOPE_RIGHT, CENTER_Y), 1)
    pygame.draw.line(surface, PHOSPHOR,
                     (CENTER_X, SCOPE_TOP), (CENTER_X, SCOPE_BOTTOM), 1)

def draw_beacon(surface, x, y, battery, color):
    if battery > 130:
        size = 7
    elif battery > 50:
        size = 5
    else:
        size = 3
    pygame.draw.circle(surface, color, (x, y), size)

sweep_x = SCOPE_LEFT
frame = 0
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    sweep_x = sweep_x + SWEEP_SPEED            # the sweep: Day 2's drone, on duty
    if sweep_x > SCOPE_RIGHT:                  # past the right edge: wrap
        sweep_x = SCOPE_LEFT

    screen.fill(INK)
    draw_scope(screen)
    pygame.draw.line(screen, PHOSPHOR,
                     (sweep_x, SCOPE_TOP), (sweep_x, SCOPE_BOTTOM), 3)

    for i in range(BEACON_COUNT):
        ys[i] = ys[i] - DRIFT_SPEED                 # rising: y gets SMALLER
        xs[i] = xs[i] + random.randint(-1, 1)       # the wobble
        batteries[i] = batteries[i] - DRAIN_RATE    # the drain: a tally in reverse
        if batteries[i] < 0:                        # dead: a fresh beacon takes the slot
            xs[i] = random.randint(SCOPE_LEFT + 20, SCOPE_RIGHT - 20)
            ys[i] = random.randint(CENTER_Y, SCOPE_BOTTOM - 40)
            batteries[i] = FULL_BATTERY
        draw_beacon(screen, xs[i], ys[i], batteries[i], colors[i])

    pygame.display.flip()
    frame = frame + 1          # counts the passes; timed gates read it
    clock.tick(60)

pygame.quit()
Predict Three predictions before you run. (1) What ends this run, and on which day did you learn that loop? (2) The scope's center sits at (320, 240). As a beacon rises, does its y value get bigger or smaller? (3) What happens to a beacon whose battery drops below 0?
(1) You do, by closing the window: the QUIT event arrives, the listener flips running, and the watch question turns no. It is Day 2's five-beat loop, holding twelve beacons and a sweep. (2) Smaller. On a screen, y counts downward from the top edge, so rising means y shrinking toward 0. (3) It respawns: a fresh position in the lower half of the scope and a full battery, in the same slot. Reading what a coordinate pair means in this particular situation is the skill the hinge is about to check.

Drill 7 · Reading I: the frame loop5.G.A.2

Find the patterns you already own

Read the heart of the engine, the lines inside the watch loop. Don't run anything. Every marked line is a pattern you learned this week, wearing engine uniform.

    sweep_x = sweep_x + SWEEP_SPEED            # line E
    if sweep_x > SCOPE_RIGHT:                  # line F
        sweep_x = SCOPE_LEFT

    for i in range(BEACON_COUNT):
        ys[i] = ys[i] - DRIFT_SPEED                 # line A
        xs[i] = xs[i] + random.randint(-1, 1)       # line B
        batteries[i] = batteries[i] - DRAIN_RATE    # line C
        if batteries[i] < 0:                        # line D
            xs[i] = random.randint(SCOPE_LEFT + 20, SCOPE_RIGHT - 20)

Predict Name the pattern each line wears. Lines A and C: which Day 2 pattern, and what makes them unusual? Line B: whose trick from Day 1? Line D: which Day 1 clearance check? Lines E and F: which Day 2 drill, almost word for word?
Lines A and C are the tally, running in reverse: each takes a little out every pass. A shrinking y is a rising beacon, and a shrinking battery is a dying one. Line B is Day 1's Dispatcher, nudging x left or right: the wobble. Line D is Day 1's flat checkpoint, the respawn decision. Lines E and F are Day 2's Patrol Drone, the update beat and its wrap gate, with the drone renamed the sweep. Nothing in the engine's heart is new. You could have written every line of it; the engine's only trick is doing it twelve beacons at a time, sixty times a second.
Drill 8 · Reading II: the four racks and the ladderE5-PRO-VD-?? ⚠

How the engine builds its beacons, and how it sizes them

Now read the setup, above the loop. Four empty racks, one growing loop. Beacon number i lives at slot i on every rack: that's the parallel-racks trick, and Day 2's beacons-from-a-list was its rehearsal. Then read draw_beacon: a routine with five parameters and a ladder inside.

xs = []
ys = []
batteries = []
colors = []

for i in range(BEACON_COUNT):
    xs.append(random.randint(SCOPE_LEFT + 20, SCOPE_RIGHT - 20))
    ys.append(random.randint(CENTER_Y, SCOPE_BOTTOM - 40))
    batteries.append(random.randint(60, FULL_BATTERY))
    colors.append(random.choice(BEACON_COLORS))

def draw_beacon(surface, x, y, battery, color):
    if battery > 130:
        size = 7
    elif battery > 50:
        size = 5
    else:
        size = 3
    pygame.draw.circle(surface, color, (x, y), size)
Predict After the loop runs with BEACON_COUNT = 12: what is len(colors)? Is every colors[i] guaranteed to come from BEACON_COLORS, and why? Which drill today taught the growing move? And the ladder: which Day 1 drill is it, and what size does a beacon with battery 50 get?
len(colors) is 12, one append per pass, and every colors[i] must come from BEACON_COLORS because random.choice only ever hands back an item from the rack it's given, Day 1's law. The growing move is Drill 5's append. The ladder is Day 1's Drill 10, three lanes, flat; a battery of exactly 50 is not greater than 130 and not greater than 50, so the else lane opens and the beacon draws at size 3. Read the whole engine now, top to bottom, and initial every section you can explain; tomorrow's Commission begins where your initials stop.
Hinge question · stop here until you're sure5.G.A.2

The rising number and the ladder

Part 1: one pass runs the line ys[i] = ys[i] - DRIFT_SPEED. After it, is the beacon drawn higher or lower on the screen, and is the number in ys[i] bigger or smaller than before?
Part 2: the engine calls draw_beacon(screen, 300, 200, 45, PHOSPHOR). Where is the beacon drawn, what size is it, and which line of the ladder decided?

Part 1: higher on the screen; smaller in the briefcase. If you said "higher and bigger," you're using math-class axes on a screen that counts from the top. Re-read Drill 6's second reveal before the build. Part 2: at (300, 200), a little left of center and above the middle line, at size 3. 45 fails both questions, so the else lane decided. If you got both, you're ready to rehearse for the Commission.
Field Mission · The Blueprint Rehearsal

Write routines, then draw with one

Part A, the blueprint (terminal): write two routines of your own, one with one parameter, one with two, and call them from a rack with a loop, the way Drill 4 did.

Part B, the drawing routine (window): rebuild Day 2's beacon rule through a def: write draw_beacon(surface, x, size) and call it in a loop, then hold the window open with Day 2's loop. Tomorrow your Commission asks for exactly this move with a gadget of your own.

Suggested start: Part A's one-parameter routine first. House law: one change per run.

import pygame

# --- Part A: the blueprint ---
def transmit(message):
    print(f"Transmitting: {message}")

def requisition(gadget, count):
    print(f"Issue {count} of {gadget}.")

dispatches = ["falcon is airborne", "rendezvous at dawn", "decoder secured"]
for d in dispatches:
    transmit(d)
requisition("smoke pen", 2)

# --- Part B: the drawing routine ---
pygame.init()
screen = pygame.display.set_mode((640, 480))
pygame.display.set_caption("The Rehearsal")
clock = pygame.time.Clock()

def draw_beacon(surface, x, size):
    pygame.draw.circle(surface, (123, 228, 149), (x, 240), size)

screen.fill((27, 31, 38))
for i in range(5):
    draw_beacon(screen, 70 + i * 125, 12 + i * 6)
pygame.display.flip()

running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
    clock.tick(60)
pygame.quit()
Part B is Day 2's beacon rule handed to a routine: the def holds the how, the loop holds the where. Trace the sizes before you run: 12, 18, 24, 30, 36.

Standards, pacing & evidence (teacher panel)

The pacing choice, stated plainly: Day 3 is the reading day. Exactly two new marks, def and append, arrive in the first five drills; the rest of the page is reading, and the reading is the point. Drills 7 and 8 ask recruits to name Day 1 and Day 2 patterns inside the engine (the tally in reverse, the flat checkpoint, the Dispatcher's wobble, the drone's wrap gate, the growing loop, the three-lane ladder), which is the comprehension move the whole week is built to produce. Tomorrow introduces nothing new on purpose.

Where recruits actually stall: Block A (Drills 1 to 5) runs about 40 minutes; the stall is Drill 1's prediction, where most recruits expect the def to print on its own. Let them be wrong, then run it. Block B (Drills 6 to 8 plus the hinge) runs about 45 minutes; the engine must run unmodified on every machine before the Debrief, and the common failure is pasting it below the Part A code in day3.py. Keep it as its own file. Block C, the Rehearsal and the Mission Debrief, needs a full 45 minutes.
