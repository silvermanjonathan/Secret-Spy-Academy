The Tamper Seal

Ciphers keep a message secret. A seal answers a different question: did anyone change it on the way? One letter, computed from the whole message and stuck to the envelope, catches a meddling courier by arithmetic alone. You'll also find the seal's blind spot, because honest cryptography names its own weaknesses.

Drill 1 · The sealE5-PRO-VD-?? ⚠

One letter that vouches for all of them

Sum every letter's slot number, wrap the total onto the wheel with % 27, and the landing slot's letter is the seal. Sender computes it and writes it on the envelope's corner; receiver recomputes and compares. It's the tally plus the professional's wrap, and it is the ten-year-old ancestor of the checksums guarding every file your computer ever downloads.

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
message = "MOVE THE GOLD AT NINE"
total = 0
for letter in message:
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    total = total + slot
print("Total:", total)
print("Seal:", rack[total % 27])
Predict The total lands at 276. What is 276 % 27, and which letter seals this message? Check by tens: 270 is how many full turns of the wheel?
Ten full turns of 27 make 270, leaving 6, and slot 6 is G. The seal letter means nothing by itself; its only job is to be recomputable. Anyone holding the message can produce G. Anyone holding a changed message almost certainly can't, and "almost" is this mission's honest word: you'll find the exception in Drill 3.

Drill 2 · The broken sealE5-PRO-VD-?? ⚠

The courier changes one word

Somewhere between agents, NINE became NOON. The receiver recomputes the seal on what actually arrived, and compares it against the G on the envelope.

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
message = "MOVE THE GOLD AT NOON"
sealed = "G"
total = 0
for letter in message:
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    total = total + slot
if rack[total % 27] == sealed:
    print("Seal matches. Trust the message.")
else:
    print("SEAL BROKEN. Recomputed:", rack[total % 27], "Envelope:", sealed)
Predict Which branch fires? NINE's letters sum to 35 and NOON's to 51: how far does the total move, and does the receiver learn what was changed, or only that something was?
The else fires: the total climbs by 16, to 292, and 292 % 27 is 22, the letter W. W is not G, and the courier is caught. But notice what the seal can and cannot say: it shouts that the message changed, and stays silent about where or what. One letter of arithmetic buys exactly one bit of truth, and for a courier network, that one bit is everything.

SEAL BROKEN. Recomputed: W Envelope: G
Drill 3 · The blind spotE5-PRO-VD-?? ⚠

The tamper the seal cannot see

A cleverer courier doesn't change letters; he rearranges them. NINE becomes NIEN: same four letters, new order. Run the check.

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
message = "MOVE THE GOLD AT NIEN"
sealed = "G"
total = 0
for letter in message:
    slot = 0
    for i in range(27):
        if rack[i] == letter:
            slot = i
    total = total + slot
if rack[total % 27] == sealed:
    print("Seal matches. Trust the message.")
else:
    print("SEAL BROKEN. Recomputed:", rack[total % 27], "Envelope:", sealed)
Predict Which branch fires this time, and why? What property of addition is the courier exploiting?
The seal matches, and the tampered message walks through the checkpoint. The courier is exploiting the oldest fact in arithmetic: addition doesn't care about order. Same letters, same sum, same seal, different message. A checksum built on a plain sum is blind to every shuffle, and real attackers found this hole in real systems. The repair is one idea away.

Seal matches. Trust the message.
Drill 4 · The weighted sealE5-PRO-PD-?? ⚠

Make position count

The repair: multiply each slot by its position's rank before adding, slot * (i + 1). Now the first letter counts once, the tenth counts ten times, and a shuffle moves weight around. One counter and one multiplication, and the blind spot closes.

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
message = "MOVE THE GOLD AT NIEN"
total = 0
i = 0
for letter in message:
    slot = 0
    for j in range(27):
        if rack[j] == letter:
            slot = j
    total = total + slot * (i + 1)
    i = i + 1
print("Weighted seal:", rack[total % 27])
Predict The honest message's weighted seal is O. Will the shuffled NIEN message produce O? And why does weighting catch a swap that plain summing missed?
It produces X, and the courier is caught. Swap two different letters and each now carries the other's weight: the totals trade unequal contributions, so the sum moves. The lesson underneath is the real one: a good seal must depend on what the letters are and where they stand. Modern seals, the hashes guarding your downloads, take that idea to extremes this arithmetic only gestures at, but the shape is exactly this.

Hinge question · stop here until you're sureE5-PRO-VD-?? ⚠

What the seal can promise

Part 1: a courier raises one letter by one slot and lowers a different letter by one slot. Does the plain seal catch it? Does the weighted seal?
Part 2: the seal is a single letter, so only 27 seals exist. A saboteur invents a fake message from scratch. Roughly what are the odds its seal happens to be G anyway, and what does that say about one-letter seals?

Part 1: the plain seal sleeps through it, since plus one and minus one cancel in a plain sum, but the weighted seal catches it: the two changes sit at different positions, so they carry different weights and can't cancel. Part 2: about 1 in 27. A one-letter seal is a checkpoint, not a fortress; a patient forger passes it by luck once in twenty-seven tries. Real seals are dozens of characters long for exactly this reason: every added character multiplies the forger's problem by the rack, the same law that priced the Safecracker's four-digit vault.
Field Mission · The Courier Test

Seal it, run it, catch the tamper

Part A, the sender: your own message, plain seal and weighted seal both computed, both written on the envelope slip.

Part B, the courier: pass the slip through a middle agent who may copy it faithfully, change a word, or shuffle one word's letters. Their choice, their secret.

Part C, the receiver: a checker that recomputes both seals and prints one verdict line for each. The weighted line settles arguments the plain line can't.

rack = "ABCDEFGHIJKLMNOPQRSTUVWXYZ "
message = "SHIP SAILS AT DAWN"
plain_sealed = "W"
weighted_sealed = "G"
total = 0
wtotal = 0
i = 0
for letter in message:
    slot = 0
    for j in range(27):
        if rack[j] == letter:
            slot = j
    total = total + slot
    wtotal = wtotal + slot * (i + 1)
    i = i + 1
if rack[total % 27] == plain_sealed:
    print("Plain seal: matches.")
else:
    print("Plain seal: BROKEN.")
if rack[wtotal % 27] == weighted_sealed:
    print("Weighted seal: matches.")
else:
    print("Weighted seal: BROKEN.")
Sender and receiver run the same program; only the message variable and the two envelope letters change hands.

Standards, pacing & evidence (teacher panel)

Where this fits: forty minutes, terminal only, after both Day 2 benches; % is load-bearing. The mission widens what cryptography means: Day 2 was secrecy, this is integrity, and the pair is most of the field's job description. The arc is deliberately honest: build the tool, break the tool, repair the tool, and end knowing the repair has limits too. That last move, naming your own tool's weakness, is the single most professional habit this wing teaches.

Where recruits actually stall: Drill 1's by-tens arithmetic (270 as ten turns) is worth doing aloud once. Drill 3 lands hardest if the room predicts before running; most rooms split, and the argument is the lesson. In Drill 4, the off-by-one to watch is weighting by i instead of i + 1, which silently zeroes the first letter's weight, a lovely silent bug for Thursday's collection if anyone trips it.
