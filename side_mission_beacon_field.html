Drill 1 · Two new toolsE5-PRO-VD-?? ⚠

append grows a rack; randint rolls a number

The week never needed these; this engine does, so the mission issues them. append bolts one new slot onto the end of a rack. random.randint(a, b) is the Dispatcher's sibling: instead of picking off a rack you wrote, it rolls any whole number from a to b, both ends included. The seed makes your run match the box.

import random

random.seed(2)
batteries = []
for i in range(4):
    batteries.append(random.randint(60, 200))
    print(batteries)
print("Slots:", len(batteries))
Predict How many slots does the rack have after the loop, and what does the printout look like as it grows? Could a roll ever land on exactly 60, or on 201?
Four slots, and the printout shows the rack getting longer by one each pass, which is the whole picture of append. A roll of exactly 60 is possible, since randint includes both ends; 201 is not. That both-ends rule is the one thing people misremember about randint, so say it out loud once: a to b, edges included.

Drill 2 · Parallel racksE5-PRO-VD-?? ⚠

Beacon 7 is a slot number, four times over

Target Lock tracked one target in a handful of briefcases. Twelve beacons would need forty-eight, so the engine uses four racks instead, and one slot number reads across all of them: beacon i is xs[i], ys[i], batteries[i], colors[i]. One setup loop fills all four with append and randint.

for i in range(BEACON_COUNT):
    xs.append(random.randint(SCOPE_LEFT + 20, SCOPE_RIGHT - 20))
    ys.append(random.randint(CENTER_Y, SCOPE_BOTTOM - 40))
    batteries.append(random.randint(60, FULL_BATTERY))
    colors.append(random.choice(BEACON_COLORS))
Predict After this loop, where does beacon 7 keep its battery? Why do the y rolls start at CENTER_Y instead of SCOPE_TOP? And which line uses the Dispatcher rather than its sibling?
In batteries[7]: same slot, different rack, and that answer works for its position and color too. The y rolls start at CENTER_Y so every beacon is born in the lower half of the scope and has room to rise before it dies. The colors line uses random.choice, the Dispatcher, because colors live on a rack you wrote; randint rolls numbers, choice picks belongings. Two tools, two jobs.
Drill 3 · First run of the Beacon FieldE5-PRO-RD-?? ⚠

Run it before you read it

Open beacon_field_pygame.py, or copy every line below into a file with that exact name. Change nothing yet. Run it, watch a full minute, and count how many beacons die and respawn while you watch.

import pygame, random

pygame.init()
WIDTH = 640
HEIGHT = 480
screen = pygame.display.set_mode((WIDTH, HEIGHT))
pygame.display.set_caption("The Beacon Field")
clock = pygame.time.Clock()

# ---------- THE OPS PANEL (your customizations live here) ----------
BEACON_COLORS = [(123, 228, 149), (242, 233, 211), (201, 139, 31)]
BEACON_COUNT = 12
DRIFT_SPEED = 1
SWEEP_SPEED = 4
DRAIN_RATE = 1
FULL_BATTERY = 200

SCOPE_LEFT = 120
SCOPE_TOP = 40
SCOPE_SIZE = 400
CENTER_X = 320
CENTER_Y = 240
INK = (27, 31, 38)
PHOSPHOR = (123, 228, 149)
# -------------------------------------------------------------------

SCOPE_RIGHT = SCOPE_LEFT + SCOPE_SIZE
SCOPE_BOTTOM = SCOPE_TOP + SCOPE_SIZE

# Parallel lists: beacon number i is xs[i], ys[i], batteries[i], colors[i]
xs = []
ys = []
batteries = []
colors = []

for i in range(BEACON_COUNT):
    xs.append(random.randint(SCOPE_LEFT + 20, SCOPE_RIGHT - 20))
    ys.append(random.randint(CENTER_Y, SCOPE_BOTTOM - 40))
    batteries.append(random.randint(60, FULL_BATTERY))
    colors.append(random.choice(BEACON_COLORS))

def draw_scope(surface):
    pygame.draw.rect(surface, PHOSPHOR,
                     (SCOPE_LEFT, SCOPE_TOP, SCOPE_SIZE, SCOPE_SIZE), 2)
    pygame.draw.circle(surface, PHOSPHOR, (CENTER_X, CENTER_Y), 140, 1)
    pygame.draw.circle(surface, PHOSPHOR, (CENTER_X, CENTER_Y), 70, 1)
    pygame.draw.line(surface, PHOSPHOR,
                     (SCOPE_LEFT, CENTER_Y), (SCOPE_RIGHT, CENTER_Y), 1)
    pygame.draw.line(surface, PHOSPHOR,
                     (CENTER_X, SCOPE_TOP), (CENTER_X, SCOPE_BOTTOM), 1)

def draw_beacon(surface, x, y, battery, color):
    if battery > 130:
        size = 7
    elif battery > 50:
        size = 5
    else:
        size = 3
    pygame.draw.circle(surface, color, (x, y), size)

sweep_x = SCOPE_LEFT
frame = 0
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    sweep_x = sweep_x + SWEEP_SPEED            # the sweep: Day 2's drone, on duty
    if sweep_x > SCOPE_RIGHT:                  # past the right edge: wrap
        sweep_x = SCOPE_LEFT

    screen.fill(INK)
    draw_scope(screen)
    pygame.draw.line(screen, PHOSPHOR,
                     (sweep_x, SCOPE_TOP), (sweep_x, SCOPE_BOTTOM), 3)

    for i in range(BEACON_COUNT):
        ys[i] = ys[i] - DRIFT_SPEED                 # rising: y gets SMALLER
        xs[i] = xs[i] + random.randint(-1, 1)       # the wobble
        batteries[i] = batteries[i] - DRAIN_RATE    # the drain: a tally in reverse
        if batteries[i] < 0:                        # dead: a fresh beacon takes the slot
            xs[i] = random.randint(SCOPE_LEFT + 20, SCOPE_RIGHT - 20)
            ys[i] = random.randint(CENTER_Y, SCOPE_BOTTOM - 40)
            batteries[i] = FULL_BATTERY
        draw_beacon(screen, xs[i], ys[i], batteries[i], colors[i])

    pygame.display.flip()
    frame = frame + 1          # counts the passes; timed gates read it
    clock.tick(60)

pygame.quit()
Predict Three predictions before you run. (1) Which way do the beacons travel, and what happens to a beacon that crosses the top? (2) What does the sweep do at the right edge? (3) What ends the run?
(1) They rise, wobbling, and nothing special happens at the top: no gate watches for it, so a long-lived beacon can drift out of the scope and off the window, still alive. Watch for one; it's the engine's most honest quirk. (2) The sweep snaps back to the left edge: the cipher wheel's wrap gate on a position. (3) You do, with the close button, the same QUIT listener as every window this month.

Old patterns, new costumes

Three excerpts, three patterns you own. The drain is the tally running backward. The size ladder is Day 1's three-lane elif, reading a battery instead of a clearance. The respawn is a flat gate inside the beacon loop, refilling three racks at once.

Predict What size does the ladder draw for a battery of exactly 130? Of exactly 50? And in one pass of the ring, how many times does the respawn gate get checked?
Exactly 130 fails the first rung and passes the second: size 5. Exactly 50 fails both rungs and falls to the else: size 3. A ladder's rungs are strict, and the boundary numbers always belong to the rung below. The respawn gate is checked twelve times per pass, once per beacon, inside the loop; the sweep's wrap gate, by contrast, runs once. Depth on the page tells you count at runtime, the same lesson your capstone schematic taught.
Hinge question · stop here until you're sureE5-PRO-RD-?? ⚠

The lifespan question

A beacon respawns with a full battery of 200, and the drain takes 1 per pass.
Part 1: for how many passes does it wear each size, 7, then 5, then 3?
Part 2: at DRAIN_RATE 2, what happens to those numbers, and what would you see change on the scope?

Part 1: 70 passes at size 7 (batteries 200 down to 131), 80 at size 5 (130 down to 51), 51 at size 3 (50 down to 0), then the next pass goes below zero and the respawn fires. Part 2: every span halves, a whole life in about two seconds instead of three and a half, and on the scope the field visibly churns: more respawns per minute, more small beacons at any moment. One constant, and the mood of the whole instrument changes. That's what the Ops Panel is for.
Field Mission · Retune the Field

Make the instrument yours

Part A: your colors and your crowd: rebuild BEACON_COLORS with four tuples of your own and raise BEACON_COUNT to 30. Predict first: what must the setup loop do differently for 30, and what must you change inside the ring? (Careful. The second answer is a trick.)

Part B: your physics: pick one of DRIFT_SPEED, DRAIN_RATE, or SWEEP_SPEED, predict the visible change in one sentence, then run. One change per run, as always.

Part C, stretch: a ceiling for the field: a flat gate in the update beat that respawns any beacon whose y drifts above SCOPE_TOP, so no beacon escapes the scope again. Say which existing gate you're imitating before you write it.

The trick: nothing changes but the number. The setup loop already runs BEACON_COUNT times, and the ring's beacon loop reads the same constant, so 30 beacons cost one edit. That's the payoff of parallel racks filled by a loop: the crowd size lives in exactly one place. If your instinct was to add slots by hand, you've just felt why append earns its keep.

Standards, pacing & evidence (teacher panel)

Where this fits: the post-capstone side mission, for agents who finished the week and want a second engine. Fifty minutes with pygame already installed. It deliberately carries the two moves the main week dropped when Target Lock became the capstone: append and random.randint debut here, in Drill 1, with a seed so the first meeting is checkable. Everything else on the page is reading, and the reading leans on the capstone: the drain is the streak's mirror, the respawn gate sits at the depth the schematic taught recruits to count, and the sweep's wrap is the wall gate's teleporting cousin.

Where recruits actually stall: Drill 2's "which line uses the Dispatcher" question sorts the room fast; recruits who answer it cold are ready for Part C. The Drill 3 quirk, a beacon escaping the scope's top, generates the day's best argument: is it a bug? The engine says nothing either way, which is the point, and Part C is the fix for anyone who votes yes. The Part A trick question lands best if you make the room commit out loud before the reveal.
